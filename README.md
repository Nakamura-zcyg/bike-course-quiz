# 技能試験コース暗記

二輪技能試験のコース図をなぞって順路を覚えるクイズアプリ。Vite + React + TypeScript。スマホの横向きで使う想定。

## 遊び方

| 設定 | 選択肢 |
|---|---|
| 入力方式 | **なぞる**: 指でコースをなぞる ／ **タップ**: 次に通る曲がり角を順にタップする |
| モード | **練習**: 外れた時点で止めて正しい区間を表示 ／ **本番**: 最後まで描いてからまとめて採点 |
| 判定の厳しさ（なぞるのみ） | 厳しめ 15pt ／ 標準 22pt ／ 緩め 28pt（ルートの線からの許容距離。線は道の中心からずれて描かれている所があるので、同じ道の上なら正解になる幅）。許容幅の外に 8pt 以上続けて出たら外れ |

- 採点は区間（元の図で矢印から矢印まで）単位。点数は正解した区間の割合
- 成績（挑戦回数・ベスト・前回）と区間ごとの通算ミス回数は端末の localStorage に保存する。お手本画面で苦手区間が色分けされる
- 「拡大・移動」ボタンで、1本指のドラッグ・2本指のピンチによる拡大縮小に切り替わる。PC ではホイールで拡大できる

## 判定の仕組み

- **なぞる**: ルート上の「進み位置」を持ち、描いた点を進み位置の少し手前〜少し先（許容幅の 1.5〜3 倍）の範囲だけで照合する。交差点や同じ道を 2 回通る区間でも周回を取り違えず、逆走や先の区間へのショートカットは外れになる
- **ショートカットは正解扱い（仕様）**: 判定は線からの距離だけを見るので、クランクや S 字の中を直線で抜けても許容幅に収まれば正解になる。覚えたいのは順路の順番なので、課題の中の形までは問わない
- **本番の採点**: 外れたあとは、近い先へ戻れば数点で復帰、遠い先へ飛んだ場合は 80pt 沿ってなぞったときだけ復帰とみなし、間の区間を未走行として誤りにする
- **タップ**: 候補点は番号ポール（交差点の中心）と、ポールから離れた曲がり角。1号・2号どちらかの線が曲がる所はすべて候補になるので、候補そのものは答えにならない。同じ交差点で線が何本並んでいても候補は 1 つ（間に島の縁や縁石を挟まなければ同じ交差点とみなす）。内側の道と外周の道は縁石で隔てられているので別の候補になる。クランク・S 字は入口・出口と中ほどの 1 点だけ（中の曲がり角は数えない）。
- **タップの省略**: ルートがまっすぐ通り抜けるだけの交差点は飛ばしてよい。直線の先の点をタップすれば、間の点は通過したとみなす（曲がる点は飛ばせない）。本番は正解手順との編集距離で照合し、通り抜けるだけの点の抜けは誤りにしない

しきい値はすべて [src/constants.ts](src/constants.ts) にある。

## コースデータの作り方

PDF の赤線は「区間ごとの線の輪郭＋矢じり」のベクター図形なので、座標をそのまま取り出している（手入力ではない）。

```bash
pip install pymupdf numpy pillow
python tools/extract_course.py <コース図.pdf> --prefix kogata --class-name 小型二輪
```

- `public/courses/<id>.png`: 赤線を消した背景（PDF の描画命令から赤の塗りだけ外して描画）
- `public/courses/<id>-original.png`: 元の図（お手本の「元の図」「重ねて確認」用）
- `src/data/<prefix>.json`: 区間ごとの座標列（pt。走行順・向き付き）、タップ候補と各コースの正解手順（壁の判定に PDF 埋め込みの地図画像を使う）

別の PDF を追加したら [src/data/courses.ts](src/data/courses.ts) で読み込む。お手本画面の「重ねて確認」で、抽出した線が元の赤線に重なっているかを確認できる。

## 開発

```bash
npm install
npm run dev
npm run build
```

main に push すると GitHub Actions（[.github/workflows/deploy.yml](.github/workflows/deploy.yml)）で GitHub Pages に公開される。リポジトリの Settings → Pages → Source を「GitHub Actions」にしておく。
